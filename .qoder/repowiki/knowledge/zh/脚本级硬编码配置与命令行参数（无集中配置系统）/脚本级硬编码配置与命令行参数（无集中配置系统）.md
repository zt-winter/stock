本仓库未实现统一的配置文件加载机制，不存在 config/、*.yaml、*.toml、*.env 等集中式配置。所有运行期配置均以“脚本内常量 + argparse 命令行参数”的方式分散在各独立脚本中，属于典型的“扁平脚本 + 硬编码配置”风格。

具体表现：
- 数据库路径：每个脚本各自定义 `_DB_PATH` / `DB_PATH`，均指向同目录下的 `financial_data.db`（如 `financial_report.py:79`、`etf_weight.py:29`），通过 `Path(__file__).parent / "financial_data.db"` 拼接，不依赖环境变量或外部文件。
- 采集目标列表：`financial_report.py` 的 `__main__` 块中以 Python 列表 `STOCKS = [(code, market, start_year), ...]` 形式声明待采集股票，新增标的只需在此处追加一行。
- 网络请求头/超时/分页大小等运行时参数：以模块级常量或函数默认参数形式硬编码在源码中（如 `etf_redemption.py` 中的 `headers`、`timeout=15`、`_DC_PAGE_SIZE=100`、`_DC_INTERVAL=1.0`；`etf_weight.py` 中的 `_DC_PAGE_SIZE`、`_DC_INTERVAL`、`batch_size=60`）。
- 命令行参数：`etf_redemption.py` 和 `etf_weight.py` 使用 `argparse.ArgumentParser` 暴露 `--market`、`--fund-code`、`--date`、`--detail`、`--save` 等开关，作为唯一的外部可配置入口；`financial_report.py` 无 CLI，仅支持直接运行并编辑源码中的 `STOCKS` 列表。
- 无环境变量读取：全仓搜索未发现 `os.environ`、`getenv`、`dotenv`、`load_dotenv` 等用法，因此不支持通过 `.env` 或环境变量注入配置。
- 无配置校验/默认值分层：各脚本对缺失参数的处理是“打印错误后退出”，没有 fallback 到默认值的策略层。

开发者应遵循的约定：
- 若需修改数据库位置，直接编辑对应脚本中的 `DB_PATH` / `_DB_PATH` 赋值行。
- 若要调整采集标的，在 `financial_report.py` 的 `STOCKS` 列表中增删元组项。
- 如需对外暴露可调参数，优先复用 `argparse` 模式（参考 `etf_redemption.py` 的 `main()`），避免新增隐式全局变量。
- 暂不建议引入外部配置文件，以保持单脚本即运行的轻量特性。
